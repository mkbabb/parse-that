# U.W4 — ordered regex VM with bounded execution

## Goal

Execute canonical HIR with correct branch order, assertions, captures, and lazy
repetition under explicit resource bounds.

## Work

1. Lower HIR to a compact immutable instruction program with validated targets,
   character predicates, capture slots, and source provenance.
2. Implement an ordered Thompson/Pike-style VM or simpler proved engine selected
   by the prototype comparison. Thread priority must encode alternation and
   greedy/lazy order rather than recovering it after matching.
3. Evaluate assertions without consuming input; preserve capture state along the
   winning path; terminate empty loops and ambiguous programs.
4. Return success/failure plus offsets/captures/diagnostics and a run report. Time,
   thread, and memory limits are explicit typed failures, never partial matches.
5. Add a literal/class fast path only after it is proved observationally equal to
   the VM and materially wins; otherwise keep one engine.

## Gates

- U.W0 semantic/budget vectors pass across interpreter and any fast path.
- Generated differential/property corpora agree on match, offsets, ordering, and
  captures across hash seeds and repeated runs.
- Malformed programs cannot be built through public APIs; fuzzed inputs do not
  panic or exceed the declared wall.
- Profiles justify every instruction and specialization retained.

## Completion

The old epsilon-anchor, greedy-lazy collapse, and split execution routes are gone;
one bounded VM gives PT-R executable semantics.
