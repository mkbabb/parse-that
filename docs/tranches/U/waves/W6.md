# U.W6 — TS/Rust/WASM semantic crossing

## Goal

Prove one qualified coordinate, result, diagnostic, regex, and value contract
across the TypeScript and Rust implementations and the WASM boundary.

## Work

1. Declare UTF-16 code-unit positions for JavaScript-facing data and UTF-8 byte
   positions for Rust internals, each branded/qualified. Conversion requires the
   source and rejects invalid boundaries.
2. Define one semantic manifest for parser result variants, expected sets,
   commitment/recovery, captures, spans, and value layouts. Generate language-
   specific carriers where useful; do not duplicate hand-maintained schemas.
3. Compare TS invocation behavior with the Rust run kernel for literals, choices,
   recursion, recovery, regex, astral text, invalid text, and nested invocations.
4. Make WASM transport only declared carriers with checked source identity and
   ownership. Remove manual copies and stale packages.
5. Document unavoidable one-home differences explicitly; layout symmetry is not
   permission to expose Rust internals or add empty mirror modules.

## Gates

- Cross-language corpus matches value, success/failure, qualified offsets,
  diagnostics, captures, and budgets.
- Boundary/property tests cover every scalar and astral position and reject split
  surrogate/UTF-8 positions.
- Schema and bindings regenerate byte-identically and stale manifests fail load.
- The crossing graph has one producer and one consumer route per artifact.

## Completion
