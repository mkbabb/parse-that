# T.W6 — coordinate and consumer truth

## Goal

Qualify character domains at public crossings and prove the new package against
realistic consumers without inventing an unsupported Unicode dispatch feature.

## Work

1. **ASCII dispatch contract.** Represent supported one-byte dispatch keys with a
   constructor/runtime validator and a narrowed type because `Record<string>`
   promises inputs the LUT cannot address.
2. **Qualified positions.** Distinguish UTF-16 indices, UTF-8 byte offsets, Unicode
   scalar positions, line, and column in public result/source-map shapes because
   Rust/JS crossings otherwise compare unlike numbers.
3. **Conversion ownership.** Centralize checked conversions at boundaries and keep
   hot internal indices native to their runtime because branding every loop counter
   would add ceremony without safety.
4. **Consumer craters.** Install the tarball into minimal ESM, Vite, worker, and
   declaration consumers because package correctness must be independent of Value.
5. **Unicode trigger.** Search grammar and sibling consumers; implement Unicode
   dispatch only if a concrete grammar requires it because current evidence supports
   an enforced ASCII contract, not a new feature.

## Gates

- Unsupported dispatch keys fail construction and cannot compile through the
  literal helper.
- Multibyte corpora round-trip JS indices to Rust byte spans through explicit
  conversion maps.
- Diagnostics render identical source locations before and after packing.
- No unqualified numeric coordinate crosses the TypeScript/Rust/WASM boundary.
- All isolated consumer craters pass against the packed artifact.

## Completion

PT character/coordinate and package-consumer locks are green without claiming
current Value 4 adoption.
