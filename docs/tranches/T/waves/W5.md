# T.W5 — source and package DAG transposition

## Goal

Break the core and domain-parser SCCs, obtain a true inward core, and publish one
module identity from one artifact graph.

## Work

1. **Feature modules.** Group `model`, `run`, `parser`, `combinators`, `primitives`,
   `memo`, `diagnostics`, `debug`, and domain parsers by ownership because the
   current parser/state/utils/leaf/debug cycle hides every direction.
2. **Sink entrypoints.** Make barrels and package entries import-only sinks; domain
   parsers import concrete features because importing the root from a domain forms
   the second SCC.
3. **Strip repeated names.** Within a module, use `memo/cell`, `memo/grow`,
   `diagnostics/render`, not repeated module prefixes because the directory already
   carries that information.
4. **External isomorphic tests.** Move tests to `test/<source path>` and keep package
   craters under `test/package` because flat tests and production test hooks obscure
   ownership.
5. **One loader policy.** Prototype ESM-only and explicit dual-condition consumers;
   select one by supported consumer evidence because identity mismatch alone does
   not prove which policy is correct.
6. **Artifact closure.** Build before tests, pack the tarball, and install it into
   disposable Node and Vite projects because local `dist` and skipped tests are not
   publication evidence.

## Gates

- Source, runtime, declaration, and built-chunk projections contain no SCC with
  more than one feature module.
- `core` does not transitively load memo, debug, JSON, or CSV unless its manifest
  explicitly exports and budgets that feature.
- One `Parser` identity is observed across every supported subpath and environment.
- Missing or stale `dist` fails before tests; no test has a skip-on-artifact path.
- Packed consumers use only declared exports and contain no workspace source edge.

## Completion

The old module tree and losing loader format are deleted; package manifests,
declarations, and tests describe only the selected topology.
