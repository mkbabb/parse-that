# T.W2 — result and combinator algebra

## Goal

Make success, recoverable failure, and committed failure explicit and make every
runtime value inhabit its inferred TypeScript type.

## Work

1. **Result algebra.** Introduce a discriminated `ParseResult<T>` with cursor,
   diagnostics, and failure evidence; add `parseOrThrow` because `parse(): T`
   currently returns stale or absent values on failure.
2. **Sequence truth.** Use const-generic readonly tuples for `sequence`; provide
   explicit `left`, `right`, `between`, and mapping projections because magic
   discard behavior made `all`, `wrap`, and `trim` declarations lie.
3. **Assertion truth.** Give negative and positive lookahead zero-width result
   types and values because assertion success must not masquerade as parsed input.
4. **Choice and chain.** Infer unions without accepting an artificial `S | T`
   argument constraint; prove falsy values and branch order because current casts
   hide variance errors.
5. **Progress law.** Reject or fail repetition of a zero-width-success parser
   because otherwise a lawful type can still produce nontermination.
6. **Compile-fail corpus.** Pair every runtime vector with accepted and rejected
   assignments because declaration generation alone cannot prove soundness.

## Gates

- Runtime/type mirror covers every exported combinator and each failure branch.
- Sequence tuples preserve literal positions through 0, 1, 2, 3, and variadic
  arities.
- `between`/`trim` return the body value; assertions return their declared unit or
  boolean witness; no array/value ambiguity remains.
- Parser laws cover map identity/composition, sequence associativity modulo tuple
  reassociation, choice identity, lookahead non-consumption, and repeat progress.
- Public declarations contain no `any`; every unavoidable internal erasure is
  confined to one audited call boundary.

## Completion

All prior runtime/type divergence probes invert to green and no compatibility
overload preserves the old shapes.
