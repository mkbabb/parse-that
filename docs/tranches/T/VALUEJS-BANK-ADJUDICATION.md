## What the partial uplift actually is

The bank is a researched defect/candidate packet and a machine handoff template.
It is not a parse-that source uplift, package candidate, or value.js adoption:

- the bank itself says no parse-that source was changed;
- the YAML leaves npm integrity, CSS corpus digest, and CSS projection digest
  empty;
- its pinned parse-that/BBNF revisions predate the active SK-V25 campaign and
  must not be treated as current artifact identity;
- value.js 4 currently has no package or source dependency on parse-that; its
  active CSS grammar is handwritten;
- no packed candidate, clean install, loader proof, migrated consumer, or
  three-arm control measurement exists.

Calling this “partial adoption” would therefore be false. It is partial uplift
**research**: executable counterexamples, consumer requirements, candidate
families, corpus design, and a return schema.

## Findings admitted

The bank probes were independently rerun during the SK-V25 census. The following
mechanisms are correct and bind Tranche T:

1. diagnostics enablement and recovered evidence are process-global and leak
   across invocations;
2. public raw execution bypasses the epoch boundary and can replay a memoized
   value from another source;
3. recovery rollback pops a global last item rather than restoring a
   transaction-owned journal;
4. returned failure state, parser observer state, and the declared `parse(): T`
   surface disagree;
5. sequence projection, wrap/trim, negation, cloning, and state mapping have
   runtime shapes that contradict their declarations;
6. the dispatch type accepts arbitrary strings while the implementation only
   supports a restricted byte domain;
7. EOF regex failure can omit furthest/expected evidence;
8. the advertised core participates in runtime SCCs and pulls the packrat
   chunk; it is not an inward dependency cut;
9. ESM and CJS constructors have different identities;
10. the ordinary test command can pass while distribution artifacts are absent
    or skipped.

Two framing corrections are permanent:

- the reproduced failed sequence retained stale value `"a"`; the bank's exact
  `undefined` observation is not the returned-state fact;
- non-ASCII dispatch is not intrinsically forbidden. The defect is that the
  public `Record<string, ...>` neither expresses nor rejects the implementation
  domain.

The July 5 PT-E asks are therefore accepted in sharpened form:

- PT-E1 becomes invocation-owned diagnostics/recovery/evidence, not merely a
  scoped collection wrapper;
- PT-E2 becomes exact combinator runtime/type laws over the whole definition
  algebra, not local generic annotation tightening;
- PT-E3 remains a recorded dormant candidate. Pratt earns a bounded expression
  role only by beating the sealed direct formulation on real grammar evidence.

## Selected disposition

The bank's clean-reset family won the execution ownership question but not every
surface detail. Tranche T selects immutable private definition nodes, one sealed
evaluator, invocation-local state, exact outcome variants, transactional
checkpoints, per-run memo/LR cells, and scoped choice commitment. The v1 and v2
invocation prototypes were subsequently falsified; v3 is a superseding candidate
and must survive its own two critics plus adjudicator.

The corpus/adoption family also survives intact. It owns the U.W7 three-arm
experiment:

```text
published value.js control + published parse-that
restored identical grammar + published parse-that
restored identical grammar + packed candidate
```

Semantic acceptance, value/CST projection, source fidelity, diagnostics,
recovery, and qualified coordinates precede any speed claim. Package identity is
proved by tarball hash, lock resolution, `npm ls`, loaded-byte evidence, and
absence of links/source imports. Only then are latency, allocation, retained
heap, startup, and bundle size compared.

BBNF questions route to BB-B through BB-D: qualified program identity, host
capabilities, recursion graphs, typed values, lowering, generated artifact
provenance, and the UTF-8-byte/UTF-16-code-unit crossing. BBNF is neither assumed
to share the runtime nor dismissed as an oracle before the crossing prototype.
