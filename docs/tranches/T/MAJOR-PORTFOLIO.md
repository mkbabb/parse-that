## 5. Family P — persistent replies

### Architectural center

A parser is an immutable definition whose evaluation returns an immutable reply. Cursor, value, failure evidence, diagnostics, control, memo deltas, and resource accounting are threaded as persistent values. Backtracking chooses an earlier reply; no mutable run is restored.

### Exact topology

```text

    oracle/
      model.ts

      receipt.test.ts
    package/
      harness.ts
  scripts/
    clean.mjs
    clean-tests.mjs
    receipt.mjs
  receipts/
```

No filename repeats `persistent`, `reply`, or the package name under a directory already carrying that identity.

### Smallest independently useful implementation

- immutable grammar definitions;
- literal, sequence, ordered choice, map, lookahead, repetition, recovery, and cut;
- discriminated complete/prefix results;
- immutable expected-set and diagnostic evidence;
- direct and mutual left recursion through persistent memo fixed points;
- JSON subset and arithmetic-expression fixtures;
- nested invocation isolation without an ambient run object.

This minimum is useful even if not selected: it provides a reference result/effect algebra and a mutation-free checkpoint oracle.

### P born-RED gates

- mutating a returned reply changes a later parse;
- a failed branch leaks value, diagnostic, recovery, or cut evidence;
- a persistent memo answer from one source replays on another;
- direct or mutual LR diverges or publishes a partial answer;
- zero-width repetition loops;
- 100,000-token right recursion exhausts the host stack;
- callback throw leaves a retained memo/control frontier;
- allocation grows superlinearly on deterministic nonambiguous input.

### P independent oracle

A separately authored small-step evaluator enumerates bounded parser trees and returns normalized observations. It may use mutable local variables but may not share P’s reply, memo, or control types.

### P resource contract

A `Limits` value is mandatory; implicit infinity is forbidden.

- `maxSteps`: 10,000,000;
- `maxReplies`: 1,000,000;
- `maxMemoCells`: 500,000;
- `maxDiagnostics`: 1,024;
- `maxExpected`: 256;
- `maxValueNodes`: 1,000,000.

Exhaustion is a non-backtrackable `Resource` result and exposes no partial value.

### P hard stop

Stop P after P.W1 and disposition it **HYBRID-DONOR** or **RETIRE** if either condition holds twice on paired samples:

- persistent reply allocation exceeds the matched mutable control by more than 25%;
- direct/mutual LR requires mutation hidden behind the public persistent claim.

Do not build a custom allocator to rescue P before disposition.

### I born-RED gates

- an edit inside a surrogate pair or UTF-8 sequence is accepted ambiguously;
- a reused node overlaps the invalidation region;
- an unchanged remote subtree loses identity without proof;
- GLR conflict resolution drops an alternative;
- diagnostic coordinates fail to shift after edits;
- retained revisions grow without a bound;
- a no-op edit changes the tree digest.

- `maxEditCountPerBatch`: 1,024;
- `maxInvalidatedTokens`: explicit per operation;
- `maxSteps`: 10,000,000.

- Do not add generalized combinator compatibility to justify the prototype.
- Do not port to Rust/WASM until a real edit consumer and a clean-equivalence receipt exist.

### Smallest independently useful implementation

- chunk-fed string or byte source with explicit source identity;
- `Need` versus terminal failure;

### S born-RED gates

- concatenating chunks changes semantics relative to whole-input parsing;
- premature chunk end is reported as failure rather than `Need`;
- EOF after `finish()` remains `Need`;
- split escape, surrogate, or UTF-8 sequence is misdecoded;
- a branch reads released input;
- a returned span points into released storage;
- retained bytes grow with total input after steady state;
- a grammar with unbounded rewind seals without an explicit refusal or bound;
- backpressure causes duplicated or lost events.

### S independent oracle

For every bounded input, concatenate all chunks and run the common whole-input reference. Enumerate every chunk partition for short inputs and deterministic seeded partitions for long inputs. Reduce streaming events to the same normalized product before comparison.

- `maxRewindBytes`: 32,768;
- `maxPinnedBytes`: 65,536;
- `maxEventsPerFeed`: 65,536;
- `maxStepsPerFeed`: 1,000,000;
- `maxDiagnostics`: 1,024;
- no returned value may borrow released input.

A 64 MiB generated stream with 1–7 byte chunks must reach an RSS plateau after warmup; total retained parse-owned bytes must stay below the declared buffer, pin, event, and fixed-structure sum.

### S hard stop

- **RETIRE** if correctness requires retaining the whole source or if the first real consumers all require unbounded rewind/value materialization.

## 15. Family disposition rules

- **ADVANCE** — all minimum and advance cells pass, cost ceiling passes, holdout is clean, and two consecutive lock audits are clean.
- **HYBRID-DONOR** — the family is not a complete core, but one named organ has an independent semantic and cost win that can be transplanted without preserving a second execution path.
- **BANK** — the minimum is independently useful, but no current consumer justifies production. The row must name its reactivation trigger.
- **BLOCK** — a specific missing primitive prevents truthful evaluation. Reopen only when a materially new mechanism is proposed.
- **RETIRE** — the family is semantically wrong, dominated twice, or requires violating a binding invariant. Its receipts remain; implementation is deleted when the winner transposes.
- No partial family may be called complete.
- No family may be deferred without one of these dispositions.

Named bank triggers:

- P: a consumer requires immutable parse snapshots or reply replay.
- G: a shipping grammar requires preserved ambiguity.
- I: an editor/service requires repeated edit parsing and provides a real trace corpus.
- S: a shipping consumer supplies inputs larger than the bounded resident envelope.
- A: generated runtime interchange is required by bbnf or Value and direct interpretation cannot meet the package/cost budget.
