## Tighter N2c source law

### 1. Version-object authority

A memo entry must retain the exact immutable source-version object or an
unforgeable owner-issued handle that resolves to that object. The source
version contains its immutable parent object and edit. A string `versionId`
is diagnostic metadata only and cannot establish ancestry, branch identity,
or relocation authority. Relocation must reject a missing object, non-ancestor,
cycle, forged parent, duplicate label on another branch, or source/hash drift
before reuse. Every coordinate-bearing field, including terminal offset,
failure/frontier coordinates, nested spans/slots, examined range, and rollback
or recovery positions, must relocate through the same checked edit map. Exact
depth and max-depth contribution must be retained or recomputed; absence is
not equality. In-progress left-recursion state never persists.

### 2. One pure dependency-injected production validator

`preflight-n2c.mjs` must define one internal production validator over an
explicit dependency-injected input object. The validator may not read files,
environment, clock, randomness, process state, globals, or network directly.
The future owner/executor supplies authenticated bytes and external trust pins.
The same validator and predicates must judge baseline, mutants, leaf controls,
and control-of-control.

No input may provide `status`, `green`, expected reason, selected mutant ID, or
case-specific branch key. The validator derives status solely from consumed
bytes and returns the first owning reason. Literal GREEN result objects,
pre-filled equality booleans, caller summaries, or a second shadow validator
are fatal.

### 3. Authenticated raw and transition closure

Every proposed gate must consume its exact authenticated raw bytes. Every
edit transition binds run, grammar/action/environment/source-version identity,
parent object/handle, edit bytes and UTF-16 offsets, examined dependencies,
reuse decision, effects, complete control and candidate products, and terminal
reason. Each transition is represented exactly once; no summary substitutes
for rows, and no aggregate can be emitted before the terminal raw record.

The source must be capable of rejecting missing, extra, duplicate, reordered,
cross-run, cross-product, or unauthenticated transitions. A caught exception
must produce a raw terminal-error row before any aggregate; otherwise the
packet is invalid, not merely failed.

### 4. Concrete production-consumed hostiles

The source must express real input transformations for at least:

- missing, string-only, forged, cyclic, duplicate-label, and cross-branch
  version lineage;
- negative-EOF and examined-beyond-consumed invalidation;
- environment mutation and arbitrary source read outside the consumed span;
- dropped, duplicated, reordered, or replayed semantic effects;
- diagnostics/recovery/fault/provenance/depth policy changes;
- M2 product byte, final-offset, frontier, rollback, span, slot, or effect-log
  drift;
- transition omission, duplication, reorder, summary substitution, and
  aggregate-before-raw; and
- a leaf-only bypass using the exact production predicate and product path.

Leaf-only control-of-control must mutate one production-consumed leaf, prove
that only its owning row changes for the exact owning reason, and prove that
non-owner rows remain byte-identical. Synthetic strings outside the production
path are not controls.

not the whole semantic oracle. A later execution must authenticate a rebuilt
