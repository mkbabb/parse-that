## Control, semantic, and consumer truth

Accepted M2 at `de36d57dccdd20068b8c11a78f6e83d42e7d681f` is the speed
control, not the complete semantic oracle. It knowingly precedes complete
scalar rollback and typed pre-`RangeError` recursion. Current M3 behavior is
the semantic obligation despite its performance rejection. Admission therefore
requires both: measure against exact/rebuilt M2, and compare the candidate to a
full semantic-law envelope containing M3 rollback/depth behavior plus the
banked recovery, provenance, and result laws. “Equal to M2” alone is RED.

The current public ABI is `ParserFunction(state) => ParserState` through
`.parser`, with arbitrary `map`, `mapState`, `chain`, and `call` callbacks and
opt-in module-global packrat. That callback surface is the decisive N-IETM
purity/version problem. A callback without a stable action identity and a
proved dependency/effect contract is never reused across versions.

The logical `jsonParser` is `jsonValue.trim()` without `eof()`. Every
whole-document assay must append EOF or independently assert the final offset;
otherwise prefix acceptance is a false green.

Current Value imports no parse-that code. It owns 19 public `/css` functions
and a handwritten grammar/AST/result surface. Its `parseDeclarations` path is
fail-fast: a malformed known declaration fails the complete stylesheet. Thus a
benchmark that labels current Value as recovery-preserving without returning
that fail-whole behavior is invalid. Broad non-test `parseStylesheet`
consumption belongs to Keyframes, not Value.

Full CSS/WPT conformance is absent. The 753 Webref corpus contains names, not
grammars. The isolated CSS prototype is a nested CSS-shaped region with nine

## Primary research anchors

External claims are hypotheses, never parse-that evidence.

- Dubroy/Warth, [Incremental Packrat Parsing](https://ohmjs.org/pubs/sle2017/incremental-packrat-parsing.pdf):
  persistent memo results, full examined intervals, edit invalidation, and
  relocation. Its central correctness law is fresh-parse equivalence.
- Yedidia/Chong, [Fast Incremental PEG Parsing](https://people.seas.harvard.edu/~chong/pubs/gpeg_sle21.pdf):
  interval-tree memo storage, lazy shifts, tree-structured entries, explicit
  cold-parse and memory trade-offs.
- Acar/Blelloch/Harper, [Selective Memoization](https://arxiv.org/abs/1106.0447):
  explicit equality, dependency, and space control. This supports a derived
  eligibility law, not blanket memoization.
- Ford, [Packrat Parsing](https://pdos.csail.mit.edu/~baford/packrat/icfp02/):
  unlimited lookahead and longest-match through memoized top-down parsing,
  with the associated space burden.
- Yallop/Xie/Krishnaswami, [flap](https://arxiv.org/abs/2304.05276):
  deterministic Greibach normalization and staged token-free code. Its 2–6x
  report is external and does not satisfy any local plane.
- Ohm, [Compiling PEG expression trees to WebAssembly](https://ohmjs.org/blog/2026/03/12/peg-to-wasm):
  lower IR, inlined expression structure, tagged linear-memory nodes, bump
  regions, chunked binding stacks, block-sparse packrat, specialization, and
  lazy materialization. Its speed/memory reports are external.
- van Binsbergen/Scott/Johnstone, [GLL parsing with flexible combinators](https://ir.cwi.nl/pub/29666):
  non-binarized combinator grammars over a generalized top-down executor.
- Jia/Kumar/Tan, [verified derivative VPG generation](https://arxiv.org/abs/2109.04258):
  visibly classified call/return/internal alphabets, linear parsing, parse
  forests, and verified core correctness.
- Hutchison, [Pika parsing](https://arxiv.org/abs/2005.06444): reverse dynamic
  programming for left recursion and recovery, with a documented large
  constant on complex grammars.

On this host, V8 reports WASM tier-up enabled, but JS-to-WASM wrapper inlining
and WASM string references are experimental and disabled. RegExp tier-up is
enabled after one interpreter tick; the alternative non-backtracking RegExp
engine is experimental. Therefore every WASM family pays an explicit UTF-16
transfer/crossing assay, and every RegExp family keeps cold and hot planes
separate.

## Orthogonal family atlas

### N-IETM — effect-aware, edit-indexed transactional memoization

Disposition: **KEEP — primary cross-version family**.

Load-bearing primitive: persistent parse-result dependencies across source
versions, not a faster per-run carrier. Each reusable entry binds:

- stable parser-graph identity and immutable grammar/action hash;
- old source version plus a relocatable interval anchor;
- consumed interval and the complete read/lookahead footprint, including failed
  ordered-choice arms and negative results;
- complete immutable value/span/slot/fault/frontier/rollback/recovery/
  diagnostic/provenance product;
- child-entry dependencies and effect summary; and
- a purity/version judgment for semantic actions.

An edit maps unaffected anchors forward and invalidates every entry whose read
or dependency footprint intersects the edit or whose graph/action/effect
identity changes. Arbitrary `.map`/`.chain` closures that observe mutable
external state are non-reusable unless their dependency/version contract is
proved; they rerun otherwise. A piece table, rope, or interval tree is only a
private prototype substrate.

Why it is orthogonal: M1–P6 discard per-run state after one source. Current
packrat uses `(parser, offset)` cells inside an armed parse epoch. Its completed
cell is only `{offset, value, isError}`; `MEMO`, `HEADS`, `LR_STACK`,
`CURRENT_SRC`, and `GROWING` are intentionally fresh and discarded at each top
parse. Keys omit grammar epoch, source version, diagnostics, edit relocation,
and action environment. In-progress left-recursion heads/seeds must never
persist. `diagnosticsEnabled` is global, sticky RegExp does not expose its full
examined frontier, and arbitrary callbacks may read closure/source state
invisibly. N-IETM makes those missing identities and cross-version reuse
load-bearing. Patching current packrat is therefore forbidden; the first
prototype is isolated and private.

Cost model:

```text
cold = fresh parse + trace/memo construction + immutable product
edit_i = edit-map + invalidation + dependency propagation + rerun + product
NetBenefit(K) = sum(fresh-M2(version_i))
              - (cold + sum(edit_i) + memory/GC + startup/package
                 + measured migration/validation)
```

Cold first parse remains a binding row against fresh M2. Every edited version
is compared to a new full M2 parse of identical bytes. N-IETM may target
**PL-BE only**: cold index construction adds work, so strict PL-3X/PL-2X cannot
pass their every-row law. Local edit rows may report observed 3x/2x ratios, but
those ratios are descriptive and grant no strict-family milestone.

The smallest sound private F0 uses an immutable `SourceVersion` and completed
`MemoEntry` values binding grammar epoch, rule, start, entry depth, match length,
examined length, examined EOF, source-slice hash, relocatable immutable product,
relative failure frontier, and max-depth delta. A persistent shift interval
tree removes starts inside the replaced domain, invalidates examined rather
than consumed intervals, lazy-shifts proven-safe right-hand entries,
revalidates source slice/EOF, rebases nested spans, and replays ordered failure
contributions. Recovery, diagnostics, faults, opaque RegExp, arbitrary
callbacks, and custom parsers are initially `nonReusable`; all source reads are
instrumented.

CSS projection: one immutable edit stream must include insert/delete/replace at
beginning of file, comments, strings, escapes, names, declaration boundaries,
nested functions/blocks, unordered `&&`/`||` values, malformed recovery
frontiers, and opaque syntax. Required measures are affected/read spans,
relocated/invalidated/reused cells, edit latency, cold time, retained and peak
heap, allocation/GC, package size, and exact consumer break-even.

Fatal counterexamples: a previously failing arm becomes successful after an
insertion outside its consumed span; a recovery diagnostic reads beyond its
consumed interval; external action state changes without invalidation; span
relocation changes UTF-16 bytes; retained heap grows without a bounded policy;
or any edit product differs from fresh M2. The family retires if purity forces
all Value/JSON semantic nodes to rerun, invalidation approaches full reparse on
representative streams, cold overhead cannot be recouped at measured K, or no
second consumer owns incremental reuse.

The first mandatory witness is
`string("ab").or(string(""))`: version `"a!"` takes the empty fallback after
examining both code units; edit `[1,2)="b"` must make version `"ab"` consume
the first arm. Consumed-span invalidation falsely reuses the empty success. The
CSS companion appends a closer to an unterminated comment/string that examined
EOF; a cell without an EOF dependency is stale.

Expected host signatures: interval/tree node allocation, long-lived memo
promotion, write barriers, old-space growth, GC pauses, Map/tree IC shapes, and
action-hash comparisons. These are admission costs, not implementation detail.

### N-DNF — deterministic normal-form, token-free AOT fusion

Disposition: **HOLD BORN-RED — unresolved one-shot compiler family**.

Load-bearing primitive: normalize authored combinators into a deterministic
Greibach-like form and persist one token-free direct executor before runtime.
The non-isomorphism gate is unresolved. This is not S only if the complete
grammar is normalized and runtime closure/choice construction disappears; it
is not C only if no generic table interpreter or per-process graph build
remains; it is not V only if no opcode/PC loop executes.
Authored combinators remain the grammar and there is one packaged execution
path—no interpreter fallback or compatibility output.

Cost model:

```text
build = normalization + state growth + direct-artifact generation
startup = package bytes + module parse/load
run = fused source matching + typed actions + exact recovery/product
```

Build, package, startup, first parse, hot parse, alternating grammar shapes,
allocation, and complete products remain separate rows. A persisted artifact
does not erase its package or build economics.

CSS projection: the normalizer must express CSS escapes and names, longest
match, comments/strings, nested component values, opaque authored syntax,
recovery, value-dependent `.chain`, and unordered `&&`/`||` without a token
array/tape. Its direct artifact must expose source spans and typed values, not a
recognizer-only success bit.

Fatal counterexamples: normalization/state/package blow-up; an opaque semantic
action or recovery edge falls back to the incumbent; a CSS escape changes the
deterministic lookahead class; any grammar-time compiler runs on the hot parse
path; or the direct artifact is a JS VM/table executor. The family retires if
its full-grammar cost-preserving translation is S/C/P4 or if the Value
representative cannot remain deterministic without a scanner-shaped prepass.

Expected host signatures: larger module parse/compile cost but fewer closure
allocations and call-site shapes, fewer generic combinator calls, stable direct
branches, and possible source/package inflation.

### N-WRR — parse-that-owned WASM residual runtime with region products

Disposition: **HOLD BORN-RED — unresolved substrate family, highest boundary risk**.

Load-bearing claim: the union of compiled WASM grammar control, linear
memory layout, block-sparse memo only where mechanically eligible, a
backtrackable binding stack, and tagged region output with lazy exact product
materialization. The non-isomorphism gate is unresolved. WASM alone earns
nothing. A leaf scanner is L/F3; a JS bytecode
VM compiled to WASM is V on another host; a region/finalizer without compiled
control is E/F2.

Cost model:

```text
run = UTF-16 transfer + JS/WASM crossings + WASM parse/backtrack/memo
    + tagged-region writes + immutable JS product/recovery projection
startup = compile/import/tier-up + package/module bytes
```

On Node 26/V8 14.6, WASM strings and wrapper inlining are experimental and
disabled, so no zero-copy or zero-crossing assumption is admissible. The
prototype must measure single short values, batches, and large nested sources;
compile/import, first call, tier-up, and steady state are distinct.

CSS projection: UTF-16 offsets remain original source coordinates; exact
values, spans, recovery diagnostics, opaque syntax, and failures emerge from
the same source-direct execution. Callbacks and `.chain` either specialize or
cross to JS with measured cost; no second parser path may handle them.

Fatal counterexamples: short-input transfer dominates; immutable projection
repeats E's cost; callbacks escape per node; sparse memo touches deterministic
hot paths; host/guest faults lose typed provenance; cold/package costs do not
amortize; or the artifact cannot be consumed by both JSON and Value without a
domain ABI. The family retires if removing WASM and substituting the killed V
loop preserves the load-bearing work.

Expected host signatures: ArrayBuffer/linear-memory growth, copy bytes,
crossing count, Liftoff/TurboFan tier transitions, wrapper overhead, region
high-water mark, sparse memo blocks, and JS projection allocation.

### N-GLL — scannerless GLL/GSS correctness falsifier

Disposition: **HOLD — one tiny hostile probe; no favored product route**.

Load-bearing primitive: descriptor scheduling plus graph-structured stack for
left recursion, same-FIRST ambiguity, and recovery. It is not K if
continuations are shared graph nodes rather than bounce closures; it is not V
if the probe has no generic opcode machine. It is retained only to test whether
graph sharing removes repeated work on the exact hostile surface.

The probe must include same-FIRST recovery, indirect recursion, and a bounded
unordered overlap shape with exact products. Descriptor/GSS/forest counts,
allocation, retained heap, and projection are mandatory. Any deterministic
JSON/CSS row below the active law, material parse forest, or absent two-consumer
need retires it immediately. Generalized parsing capability is not a speed
credit.

### N-VPG — visible-pushdown/transducer classification

Disposition: **SPLIT/PRUNE as a standalone full-CSS family**.

The proposed primitive is a static call/return/internal alphabet with a
table-driven visible stack and span/event emission. That is non-isomorphic to
live D only when stack action is fixed by the consumed input class and the
table removes live residual/capture work.

Raw CSS UTF-16 breaks the standalone premise: the same `(`, `)`, `{`, or `}` is
structural outside a string/comment but internal when quoted, commented, or
escaped. Turning atomic string/comment/escape matches into preclassified input
symbols either makes visibility grammar-dependent or creates a forbidden
scanner/prepass. Unordered `&&`/`||`, value-dependent chains, and forest
materialization add further gaps. Therefore no independent VPG prototype is
dispatched. Static nested-block table observations may MOVE into N-DNF or
N-WRR only if those executors consume source directly and create no symbol
tape.
